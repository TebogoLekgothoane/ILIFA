Build PASTPORT as a functional mobile MVP, not a static UI prototype.

PASTPORT lets tourists visit historical places and experience their past through their phone.

CORE FLOW:

Discover historical site
→ View real location
→ Open REAL phone camera
→ Tap “SHOW ME THEN”
→ Historical 3D/AR reconstruction appears
→ Narration plays
→ User explores the reconstruction
→ User asks the AI questions
→ User changes the historical year

TECH STACK:
- React Native
- Expo
- TypeScript
- Expo Router
- Supabase
- Supabase Auth
- Supabase Storage
- PostgreSQL
- Expo Camera
- expo-location
- react-native-maps
- Three.js / React Three Fiber or another Expo-compatible 3D library
- Expo-compatible audio library
- Supabase Edge Functions for AI requests

IMPORTANT:
The app does NOT need production-level AR tracking yet.

However, every important interaction must actually work.

==================================================
REAL FUNCTIONALITY
==================================================

CAMERA:
Use the device's REAL camera with Expo Camera.

Request camera permission and show the live camera feed.

Do NOT use a fake camera image.

The PASTPORT interface should appear over the live camera.

LOCATION:
Use the device's REAL GPS location with expo-location.

Request permission and display the user's location on the map.

Show nearby historical locations based on real coordinates.

AUDIO:
Use a REAL audio player.

When the user taps:

“LISTEN TO STORY”

actually play a narration audio file.

Include:

Play
Pause
Seek
Replay

Store narration files in Supabase Storage.

AI:
Create a working AI historical guide.

Users can ask:

“What happened here?”

“Who used this building?”

“What am I looking at?”

“What did this place look like in 1920?”

Send the request through a secure backend/Edge Function.

Never expose API keys in the mobile app.

- change the historical year
- show/hide historical elements
